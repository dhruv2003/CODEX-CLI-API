# Codex CLI API v1.4.1

Windows gateway startup fix. This version upgrades v0.1.4 through the existing signed in-app updater; the version number is intentional.

## Update from inside the app

Open **Settings → Check for updates → Download update → Install update**, then confirm. These native controls remain available even if the gateway cannot start. Existing workspaces, keys, and app data are retained.

## Download and install the app

- **[Windows x64 installer (.exe)](https://github.com/dhruv2003/CODEX-CLI-API/releases/download/v1.4.1/codex-cli-api_1.4.1_x64-setup.exe)**
- **[macOS Apple Silicon (.dmg)](https://github.com/dhruv2003/CODEX-CLI-API/releases/download/v1.4.1/codex-cli-api_1.4.1_aarch64.dmg)**

For manual installation, download only the installer for your computer. Source-code archives are not app installers.

## Fixed

- Normalize Windows extended runtime/data paths before passing them to bundled Node.js, addressing the `EISDIR` startup failure.
- Show the actual bounded runtime error instead of always claiming the port may be in use. The desktop access token is redacted.
- Report real port-binding errors when a port actually is occupied.
- Check for updates independently of gateway startup so a failed launch does not suppress the update notice.

The path normalization is a no-op on macOS. No workspace or authentication reset is required.

## Verification boundary

Release publication requires both platforms' automated tests, native startup regressions, successful packaging, original-commit provenance, and valid updater signatures. Interactive Windows shortcut launch and an installed cross-version OTA upgrade remain to be tested by the user. macOS is ad-hoc signed, not notarized; Windows is not Authenticode-signed, so operating-system warnings may appear.
