# Codex CLI API v1.4.2

Hotfix for connecting personal browser apps to the local gateway, plus the incorrect Settings/About version label.

## Changed

- Add **Browser origins** when creating an API key, including guided setup, and under **API Keys → Edit policy** for existing keys.
- Support browser API requests from each key's allowed origins, with preflight handling and per-key checks before execution. Desktop administration stays protected.
- Add a browser JavaScript example in **Connect**, alongside the existing integration options.
- Read the installed app version for Settings, About, and Updates instead of displaying stale hard-coded labels.

For TESTGPT on port 5500, add `http://127.0.0.1:5500` to its key's policy. Add `http://localhost:5500` separately if you use that address. Keep the key in your local demo's page memory; do not serve `.env` from a static site.

Existing keys, sign-ins, workspace scopes, rate limits, and expiry settings are retained. Existing keys start with no cross-origin browser permissions; server/CLI and same-origin access continue to work.

## Automatic-update support files

You do not need to download `latest.json`, `.app.tar.gz`, `.sig`, `SHA256SUMS`, or provenance files manually. The app downloads and verifies its update automatically. Use the installer links above for manual installation.

## Verification boundary

Automated tests cover the gateway policy, browser requests, existing dashboard flows, and displayed version. Hosted builds validate both platforms and updater signatures. Interactive Windows installation and an installed cross-version update require separate validation. macOS builds are ad-hoc signed, not notarized; Windows builds are not Authenticode-signed.
