Open Codex sign-in

Runs a small model request using the selected key's Codex login. Uses your account's quota.

In VS Code, open Chat → Manage Models → Add Models → Custom Endpoint. Use the configuration below. Local VS Code can connect directly; no tunnel is needed. For WSL, SSH or containers, localhost refers to that environment, so use a reachable forwarded endpoint.

This gateway supports text chat and streaming. Client tool calls and standard image uploads are not supported; images require the gateway's custom local-file input. Requests allow up to 100,000 characters of combined prompt text and a 1 MB JSON body. Model context and output-token limits are not reported by this gateway. Use VS Code's text chat mode; its tool-based Agent mode is not supported.

Advanced: HTTPS access for remote clients

Only needed when a client cannot reach your local server. Use a Cloudflare named tunnel with a hostname you control. Keep the gateway listening on loopback. The rules below expose authenticated /v1/ routes and return 404 for the dashboard and admin routes.

Remote-only HTTPS tunnel

Install cloudflared (macOS: brew install cloudflared; Windows: winget install --id Cloudflare.cloudflared), then run cloudflared tunnel login, cloudflared tunnel create codex-api, and cloudflared tunnel route dns codex-api api.example.com. Save this configuration as ~/.cloudflared/config.yml on macOS or %USERPROFILE%\\.cloudflared\\config.yml on Windows, replacing the tunnel ID, hostname and credentials path. Validate with cloudflared tunnel ingress validate. Start with cloudflared tunnel run codex-api; stop with Ctrl+C; restart with the same command. A named hostname stays the same. If you change the hostname, replace the VS Code endpoint with https://YOUR_HOST/v1/chat/completions. Confirm /, /admin/config and /healthz return 404 publicly, and /v1/models without a key is rejected.
